# Frontend

The operate panel is a server-rendered Express application for authenticated
Counter-Strike 2 operators. It registers known RCON endpoints, shows
conservative observed state, and sends explicit control commands to one
authorized server at a time.

## Architecture

- `views/*.ejs` owns document structure and route-specific content.
- `views/partials` owns the shared navigation and footer.
- `public/ts/console.ts` is the browser bundle entry for `/servers` and
  `/manage/:server_id`.
- `public/ts/common.ts` owns same-origin JSON requests, CSRF headers, toasts,
  loading state, and the shared confirmation dialog.
- `public/ts/server*.ts` owns inventory rendering; `public/ts/manage*.ts` owns
  setup, status, players, RCON, workshop, and control behavior.
- `public/css/panel.css` is the design-system entry: a single bundled stylesheet
  generated by `npm run build:css` (`scripts/build-css.mjs`) from modular
  siblings under `public/css/` (tokens, layout, nav, primitives, auth,
  inventory, manage including truth rail, feedback, utilities, responsive).
  Edit the modules, not `panel.css` directly. Night Desk Instrument is the
  default dark theme.

### Theme (Night Desk / Daylight)

- **Default:** dark (Night Desk). Tokens live on `:root`; no `data-theme` is
  required.
- **Opt-in light:** set `data-theme="light"` on `<html>`. Does **not**
  auto-switch on `prefers-color-scheme` — the product default stays night for
  evening ops.
- **Explicit dark:** `data-theme="dark"` on `<html>`, or omit the attribute.
- **Settings control:** Settings → Appearance offers Night Desk / Daylight.
  Choice is client-only: `localStorage` key `3rr.theme` (`'light'` | `'dark'`).
  `views/partials/theme-boot.ejs` runs early in every page `<head>` (before
  `panel.css`) to apply the stored value and avoid FOUC.
- Shell/nav keeps the graphite shell in both themes for brand continuity.
- Views declare `color-scheme: dark light` so browser chrome can adapt when
  light is active; CSS still defaults to night tokens until `data-theme="light"`.

Existing IDs and `data-*` attributes are behavioral contracts with browser
modules and end-to-end tests. Browser mutations stay same-origin and send the
rendered `X-CSRF-Token`. `docs/API.md` is authoritative: requested setup is not
observed state, and `unknown`, `disconnected`, and `error` remain distinct.

## Design and content conventions

- Night Desk Instrument: indigo (`--action`) for primary actions and selection,
  teal (`--observed`) for verified connection/observed state, coral for
  destructive actions, and amber for warnings or unresolved state. Legacy
  `--blue`/`--green`/`--coral` aliases remain for existing rules.
- Use Syne for restrained identity headings, system sans for reading and
  controls, and JetBrains Mono for addresses, commands, timestamps, and data.
- The manage page truth rail binds identity, endpoint, RCON state, observed map,
  players, and observation age above the workbench.
- Put target and state before controls. Keep operational headings compact.
- Prefer native elements. Controls representing state expose `aria-pressed`;
  paired controls remain neutral until a value is confirmed.
- Async work disables only its initiating control and exposes persistent or
  live feedback. Errors say what failed and how to retry.
- Shared JSON requests time out after 15 seconds. Error toasts persist until
  dismissed; success and informational notices are brief.
- Setup and workshop loaders use request generations: a late response must not
  overwrite a newer operator selection. The setup action follows its required
  game type, mode, and map controls in keyboard order.
- A live-status refresh updates the identity slate, observed-status panel, and
  RCON status label from the same normalized value.
- Consequential actions identify their target and consequence. Server removal
  explains when the saved endpoint is deleted.
- Do not add entrance choreography, decorative telemetry, marketing copy,
  animation libraries, generic wrapper components, or dashboard filler.

## Responsive and accessibility target

The primary target is keyboard-operated laptop/desktop use. At 900 px the
navigation becomes a keyboard-controlled menu, the manage layout becomes one
column, and server rows become stacked records. At 680 px forms, player data,
and truth-ledger entries reflow for touch and narrow viewports. Mobile retains
all operator actions without horizontal document overflow.

The target is WCAG 2.2 AA: landmarks/headings, skip link, visible focus, native
constraint validation, 44 px narrow-screen targets, non-color state labels,
live feedback, keyboard-contained dialogs, reduced-motion support, zoom/reflow,
and no critical hover-only interaction.

The release browser gate currently targets Chromium. Firefox/WebKit are expected
to work but are not a release claim until added to the matrix.

Stable `/css`, `/js`, font, and image URLs revalidate on each page load. Do not
mark them immutable without adding content-hashed filenames, or deployments can
leave operators on stale UI behavior.

## Development and validation

```bash
npm ci
npm run build
npm run format:check
npm run lint
npm run typecheck
npm test
npm run test:e2e
```

Run `npm run screenshots` only when intentionally regenerating the eight
canonical `docs/screenshots/*.png` evidence images. The command verifies all six
routes at 1536 px, 900 px, and 390 px, including console errors, focus order,
navigation, overflow, and clipping.

Known limits: no automated axe or screen-reader lane, no Firefox/WebKit project,
Docker validation requires a daemon, and fixture tests do not prove live
CS2/RCON behavior.
